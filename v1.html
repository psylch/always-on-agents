Always-on Agent 机制调研：Grok Bot、Raft、DeepSeek Bot 与同类产品

更新：2026-10-11（台北时间）。标注说明：【官方】=厂商文档/博客/仓库；【第三方】=媒体、社区或第三方站点。

一页摘要

  • 形态已经收敛：Grok Bot、OpenAI dots、Meta Muse 三家 always-on agent 的共同骨架是「服务器上的 agent 循环 + 每个用户一台持久云电脑（VM/容器）+ 文件化记忆与 skills + 事件/定时唤醒 + 独立模型做风险审核」。差异主要在安全边界与渠道。
  • Grok Bot（Lee Robinson 10/8 Stanford CS146S 讲座）：空闲时什么都不跑；每用户一台 Firecracker VM，闲置几分钟后快照到磁盘、下次调工具再恢复；durable workflow 断点续跑；唯一的 SendToUser 工具让 agent 可以保持沉默；Auto-review 模型批风险动作，15 秒无人回应即拦截；记忆分 Profile / Log / Notes / 搜索四层；把 cache miss 当 bug。
  • Muse 的安全架构最重：VM 内分两个安全域，agent 跑在 systemd-nspawn 容器里，凭证由 authd 托管、Sentinel 统一批准连接器动作与所有出网流量，agent 只见替代 token，并用 eBPF 做「污点出网」追踪。
  • dots：GPT-6 Astra、独立云电脑、4,000+ 应用插件；空闲时做只读「proactive research」；Custom Rules + Auto-review + 内置硬停（改密码、转账等必须人来做）。
  • Raft（原名 Slock，Botiverse）：不是单 agent，而是「人 + 多 agent」的团队协作层（频道、线程、任务、@）。agent 跑在用户自己机器上的 daemon 里，可接 Claude Code、Codex、Hermes 等外部运行时。2026-09-24 以 FSL-1.1-ALv2 源码可见（非 OSI 开源）发布 botiverse/raft-source，另有多个 Apache/MIT 周边仓库。
  • DeepSeek Bot：不是 DeepSeek 官方产品，是独立开发者 FeiZ 2026-10-07 发布的 DeepSeek Harness（DSH）插件（Apache-2.0），把 DSH 变成「主 bot + 群聊 + bot 间消息」的 IM 形态，数据全在本地；设计上明确借鉴 Grok Bot 与 Hermes Bot Mode。
  • 开源侧：Hermes Agent Bot Mode（Nous Research）和 OpenClaw 是本地/自托管路线，靠 cron routine 和 heartbeat 唤醒。
  • 标准层：唤醒方面 MCP Events 仍是草案（SEP-3415），ChatGPT（Work/dots）是目前唯一官方实现；agent 对接商家方面，Sierra + Meta 在推 Personal Agent Protocol（基于 OAuth）。

1.2 讲座要点（Stanford CS146S，2026-10-08）

来源：@leerob 帖子（2026-10-10 发布）。

  • 和普通 agent 的区别：跑在服务器上；有自己的云电脑；保存状态、记忆和 skills；只有调用发送工具时才说话；由事件唤醒；可以连续工作几个月。
  • 保持 always-on 的方式：触发器唤醒 → 跑一轮 → 闲置 2 分钟后进程停 → 云电脑闲置几分钟后执行「同步文件 → 快照 → 停机」（不会在一轮中途停）→ 下次调工具时恢复快照，登录状态保留。服务器上保存一切，VM 随时可以重建。
  • 唤醒源：用户在任意 app 发消息、routine（定时/webhook）、Slack、电话/会议、其他 agent、后台任务完成、定时 check-in。路由器去重并选定对话，同一对话一次只跑一轮；每次唤醒都记录来源。
  • 系统分三块：应用与渠道（thin client）、服务器（入口 → 每个对话一条队列 → 模型 + 循环 + 状态）、agent 的电脑（Firecracker VM + Debian 容器 + 每个 agent 一个虚拟屏幕和 Chrome）。
  • 可靠性：每条消息有唯一 ID，重试安全；推送只说「有变化」，数据以数据库为准；用 durable workflow（如 Temporal）而不是任务队列，崩溃后从断点续跑。1:1 消息可以插队打断当前一轮，群聊、Slack、routine、helper 的消息则批量排队。
  • Harness：只有一个 SendToUser 工具对用户说话，思考不外显，允许沉默；工具先给名字、细节按需加载；能力按成本从低到高尝试：已知信息 → connector → 搜索 → 浏览器 → 桌面 → 问人；截图交给 helper；每个工具的描述加 schema 控制在 4,000 字符以内；不在两轮之间增删工具。
  • 安全：独立模型做 Auto-review，15 秒无人回应即拦截；邮件、webhook 文本标为不可信；记忆只是信息，不是指令；新建 routine 需要用户确认。
  • 上下文工程：prompt 前缀保持不变以命中缓存，cache miss 当 bug 处理；用户一开始打字就预热缓存；超过 10 万 token 的长回合结束约 10 分钟后、趁缓存还热时做摘要。记忆分四层：Profile（最多 100 条 / 4,000 字符，常驻 prompt）、Log（最相关的 30 条）、Notes（短期）、可搜索记忆。
  • 方向：每个出错的 bot 都变成 eval；内环每天修 harness，外环每几个月训下一代模型；「Delete the product」，尽量少造脚手架。

1.3 官方文档补充

  • 每个 Bot 是有名字、职责、独立对话和记忆的「队友」。账号下所有 Bot 共享同一台云电脑（文件、浏览器登录、CLI 凭证都共享），每个 Bot 有自己的屏幕；关掉 app 或电脑都不会停止后台任务和 routine。overview · computer-and-apps
  • Routine：按定时或事件（如 Slack、GitHub）触发；每个 Bot 最多 50 个 routine，间隔至少 5 分钟，每个 routine 保留最近 20 条运行记录；长时间没人回应会暂停。Skill 可以通过「Teach」录制最长 10 分钟的屏幕操作生成。skills & routines
  • 电脑可以 Update（保留文件）或 Reset（从上次快照重建）。

2. OpenAI dots（2026-09-29 DevDay 发布）

  • 【官方】基于 GPT-6 Astra，有自己的云电脑，会从反馈中学习，可以 24/7 推进目标，通过插件连接 4,000+ 应用。首批面向 Pro 和 Business Premium，Enterprise 为 beta。OpenAI
  • 【第三方】空闲时做「proactive research」，只能用只读工具。安全分四层：只读模式、Custom Rules（四档：直接做 / 预先批准才做 / 先问 / 交给你）、Auto-review（Axios 称内部代号 Guardian）、内置硬停（改密码、账户间转账必须由人完成最后一步）。渠道包括 ChatGPT、Slack、Teams，iMessage/RCS 开放了候补名单。endue · The Decoder · WIRED
  • 【官方】支持 MCP Events webhook 唤醒（Work 对话与 dots）。OpenAI 文档

3. Meta Muse（2026-09-08 发布）

来源：Meta AI Research：How We Built Safety Into Muse【官方】

  • 每个用户一台专属云 VM，作为数据的 system of record；客户端直连 VM。
  • VM 内分两个安全域：agent harness（代号 Hatch）跑在 systemd-nspawn 容器里，容器内 root 映射为非特权用户，限制系统调用和内核能力。容器外是安全服务：hatch-safety 分类器、privsep 连接器 worker、hatch-authd 凭证存储、Sentinel，以及独立的 Postgres。
  • Sentinel 是连接器动作和所有出网流量的唯一授权方，在网络边界把替代 token 换成真凭证；用 eBPF 做「污点出网」：读过用户数据的进程不能再走自动放行。
  • 审批是严格的 capability，有一次性、会话级、任务级、限时、永久几档；审批弹窗直接走客户端，不经过和 Muse 的对话。
  • 浏览器子 agent 只看无障碍树，不能执行 JS；支付使用单次虚拟卡（Stripe Link）；漏洞赏金最高 30 万美元。

4. Raft（Botiverse，原名 Slock）

  • 身份：Botiverse, Inc. 的产品，创始人 RC（stdrc）此前在 Moonshot 做 Kimi CLI。2026-06-12 由 Slock 更名为 Raft，2026-07-15 发布 Raft 1.0。【第三方转载 X/LinkedIn】更名帖 · Raft 1.0
  • 产品机制【官方】：人和 agent 共用的工作区，包括频道、线程、DM、任务和 @。每个 agent 有持久身份、记忆和专长，记忆保存在用户本机；agent 自己认领任务、互相交接、设提醒、互相 review。可以接入外部 agent（Claude Code、Codex、Hermes Agent 等），使用用户自己的订阅和 key。「Computer」是用户机器上的轻量本地进程。raft.build
  • 源码开放【官方】：2026-09-24 宣布 botiverse/raft-source 源码可见，许可证 FSL-1.1-ALv2（禁止竞争性使用，每个版本两年后转为 Apache-2.0）。仓库是 release mirror，每个版本一个快照提交，不接受 PR，主张用「Prompt Request」代替 PR。截至 10/11 约 567 star、106 fork。博客
  • 架构（raft-source README）：server（API、Socket.IO 实时、持久化）、web、cli（人和 agent 共用）、daemon（在机器上运行 agent 并代理凭证，凭证经本地绑定 origin 的代理和每次启动生成的 token 下发，agent 不直接持有）、computer、raft-sdk；本地开发栈是 Postgres + Redis + 对象存储。
  • 外部 agent 唤醒：raft-external-agents 提供 Claude Code channel 插件（claude --channels plugin:raft-channel@raft）。bridge 只 POST /wake 元数据，消息正文由模型用 CLI 自己拉取；有去抖合并，监听 loopback，每个会话一个 token。

5. DeepSeek Bot（2026-10-07）

  • 身份：非 DeepSeek 官方产品。作者是独立开发者 FeiZ（GitHub FeiZhuLulu/DeepSeek-Bot），Apache-2.0，截至 10/11 约 617 star，v0.1 preview。宿主是 DeepSeek 官方的开源 agent 运行时 DeepSeek Harness（MIT，约 24.7 万 star）；DSH v0.2 于 2026-09-29 推出 macOS/Windows 桌面版。
  • 机制（README）：每个 bot 就是一个 DSH session，使用 DSH 的工具和模型。主 bot「Chief」权限最高，负责创建其他 bot 和群聊。群聊里由管理员 bot 默认应答并调度其他 bot，也可以直接 @ 某个 bot。bot 有 Markdown 记忆，可按 bot 和模型统计 token 用量。数据全在本地 ~/.dsh/bot 和 sessions/。
  • 致谢中列出的借鉴对象：AgentMemoryRepo（记忆格式）、Codex（checkpoint）、Hermes Bot Mode（每个群成员一个 session、交接）、OpenMausBot（群聊轮次）。第三方报道称它也受 Grok Bot 启发。TAU-HOME
  • 另有同名站点 deepseekbot.app（npm deepseekbot v1.1.0）：可接飞书、Slack、Discord、个人微信（仅限扫码主人的私聊），可选电脑/浏览器组件（尚未公开发布），首个动作默认先询问。文档

6. 开源与本地路线

  • Hermes Agent Bot Mode（Nous Research，MIT）【官方】：每个 Bot 就是一个 profile（~/.hermes/profiles/<bot>/，包含独立配置、记忆、skills、凭证和 SOUL.md），有一个永久的「Bot Chat」，/new 会改为压缩而不是新开会话。Routine 就是 cron。群聊 2–6 个 Bot，每条消息最多 3 轮；bot 之间用 message_agent 发消息；用 [SILENT] 表示沉默；同一 gateway 上的群聊有 durable driver，桌面端关掉后群聊仍在运行；最多保持 3 个热后端，空闲 10 分钟回收。文档
  • OpenClaw（MIT）：默认每 30 分钟一次 heartbeat，在主对话里跑一轮完整 agent turn；可配置 activeHours 和 isolatedSession。按第三方测算，isolatedSession 能把单次 heartbeat 从约 10 万 token 降到 2,000–5,000 token。OpenClaw 文档 · nventory

7. 其他相关产品与协议

  • Instinct【第三方】：邀请制，没有传统 app，通过 iMessage、WhatsApp、短信、邮件、电话交互；有持久云电脑，可能主动给用户发消息或打电话。The Verge
  • Personal Agent Protocol【官方】：Sierra 与 Meta 于 2026-10-06 发布，合作方包括 Genesys、Instinct、Rocket、Shopify、Stripe、Walmart。流程是在网站上发现能力 → 以访客或登录身份开启会话（基于 OAuth，跨渠道连续）→ 通过网站、API（MCP/OpenAPI）或企业自己的 agent 完成任务。Sierra · 规范草案
  • Claude Code【官方】：Channels（私有的 claude/channel 通知，把事件推入正在运行的会话）；Routines（定时、GitHub、HTTP 触发，每次开新会话）。Channels · Routines
  • MCP Events：SEP-3415 于 2026-10-06 提交，仍是草案；ChatGPT 是目前唯一的官方实现。PR
